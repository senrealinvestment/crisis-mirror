Crisis Mirror Architecture

Glasses = eyes / ears / discreet display.   Phone or iPad nearby = the real brain.   OpenEvidence / UpToDate = optional deep consult — not every second of listening.

One sentence: Glasses notice and display · phone/iPad decides the whisper from your local protocols · OpenEvidence/UpToDate only when you want broader evidence · after the case you grade the cue · the system gets better later, never mid-code.

Glasses (thin)

  • • Camera + mics + IMU
  • • Light on-device filters only
  • • Bone conduction + short HUD
  • • Not the main computer

Phone / iPad (brain)

  • • Gate → detect → draft cue
  • • Local Tx ICU protocol pack
  • • Safety rules (no auto-orders)
  • • Label taps after the event

Cloud (consultant)

  • • OpenEvidence / UpToDate-class
  • • Only after trigger or on demand
  • • Stripped questions, not room audio
  • • Private cloud room when needed

Learn (later)

  • • Helpful? Accurate?
  • • Latency and cost per cue
  • • Offline update only
  • • Sim lab first, then limited bedside

Safety non-negotiables

  • • Advisory language only
  • • Human remains the decision-maker
  • • No silent EMR writes
  • • Not a medical device (v0)

Why this split

  • • Glasses stay light all shift
  • • Phone has real compute + battery
  • • Fast cue ≠ waiting on the web
  • • Broad evidence still available
